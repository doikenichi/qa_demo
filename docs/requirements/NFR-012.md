## Requirement

> The engineering standards exist as executable artifacts whose own checks run in CI,
> not as prose nobody can fail.

The authoritative statement of what NFR-012 requires is in the spec at
[NFR-012 — Standards as executable artifacts](../../appointment-booking-project.md#non-functional-requirements).
This document holds the acceptance criteria, the verification plan, and the evidence links.
It restates no rule.

The artifacts are the nine skills and five review agents listed in
[Engineering standards as artifacts](../../appointment-booking-project.md#engineering-standards-as-artifacts).
That table is the authoritative set — this document does not restate the count or the names.

## Acceptance criteria

Each criterion maps to one item in the spec's four-item checklist for NFR-012.

**AC-1 (checklist item 1): Skill eval suites green; withheld-skill test deterministically fails.**  
Every skill in [Engineering standards as artifacts](../../appointment-booking-project.md#engineering-standards-as-artifacts)
has an eval suite under `.claude/evals/<skill-name>/`. The suite runs in CI and is green.

The suite loads the committed skill file itself as the model's system prompt, via the
`.claude/evals/claude-provider.mjs` provider — so deleting or weakening
`.claude/skills/<skill-name>.md` makes its suite stop passing. An eval that inlines its
own copy of the skill text measures that copy, not the artifact, and cannot satisfy this
criterion.

A separate withheld-skill configuration (the same assertions, a generic assistant system
prompt) must fail — not sometimes, always — confirming the suite is measuring the
artifact, not the model.

Each assertion targets a phrase the skill makes distinctive rather than prose the model
may reword. This is not a style preference: an assertion on ordinary phrasing goes red on
a correct answer, and NFR-001 bans the retry that would paper over it. Assertions are
chosen by repeated measurement, and a config records the candidates it rejected and the
observed rate, so a later reader can see why the current one was chosen. The provider runs with `--bare` and `--tools ""` so the withheld
run can neither auto-discover the skill from the working directory nor read it off disk;
`.claude/evals/verify-withheld.mjs` additionally rejects a run that merely errored, so a
quota or transport fault cannot be recorded as a successful proof.
See [NFR-001](../../appointment-booking-project.md#non-functional-requirements): retries are
banned everywhere; a withheld-skill test that only usually fails is not evidence and is
rewritten until it is.

**AC-2 (checklist item 2): Review agents run on every PR and record findings.**  
Every review agent in the same table runs on every pull request and posts its output as a
PR comment, including the run where it finds nothing. `.github/workflows/review-agents.yml`
drives each agent through `anthropics/claude-code-action`, which posts the comment; every
step is `continue-on-error`, so no agent can pass or fail the build. A clean-run comment is
required, not optional, and the clean run is only recorded here once observed on a real
pull request.

**AC-3 (checklist item 3): Gate fails on a planted violation of each kind.**  
The lint and scanning gate (`.github/workflows/gate.yml`) fails a pull request when it
contains a planted violation of each kind:
- Formatting breach (Spotless / Biome)
- Static-analysis finding above the configured severity (SonarCloud / CodeQL)
- Contract-lint error (Spectral on `contracts/openapi.yaml`)
- Chart-lint error (`helm lint` / chart-testing / kubeconform)
- Committed secret (gitleaks)
- Vulnerable dependency (Trivy / dependency-review)

Each proof is a **closed** pull request with its failed check visible. The planted secret is
a fabricated value that matches the scanner's pattern and authenticates to nothing — never a
real credential. None of these branches merges.

**AC-4 (checklist item 4): `docs/ai-sdlc.md` names what AI may draft and may never decide.**  
`docs/ai-sdlc.md` exists and documents, for every generated artifact class: the prompt used,
the human who reviewed it, and the decisions AI is never permitted to make. It states the
honest limitation: none of this makes a generated artifact correct; it makes the human gate
visible.

## Minimum-evidence floor

Taken directly from the spec (do not restate — see
[NFR-012 floor](../../appointment-booking-project.md#non-functional-requirements)):

> Every skill's eval suite green in CI with one proven to fail without its skill, and
> the lint/scan gate failing on planted violations of each kind.

This floor names runs and checks, not files. A committed eval config that has never run
is not evidence. A gate configured but never tested against a violation is not evidence.

This document is not finished until the Evidence table above has a run link in every row.
